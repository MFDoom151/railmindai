# Сценарий демонстрации (≈ 7 минут)

Вход: экран входа → демо-диспетчер (кнопка «Подставить») или «Посмотреть без входа». Вкладки: **Наблюдение** (карта сети и 3D-модель станции) и **Управление** (пульт диспетчера).

Онлайн-стенд: https://railtwin-digital-station.onrender.com (бесплатный хостинг засыпает — откройте за 5–10 минут до показа). Локально: `run.bat` (или `docker compose up --build`) → http://127.0.0.1:8000 .
Демо-диспетчеры: `dsp.almaty / Almaty-2026`, `dsp.shu / Shu-2026`, `dsp.astana / Astana-2026`, `dsp.karaganda / Karaganda-2026`. Для настроек нужен admin (пароль задаётся в окружении; в DEV-режиме `admin / admin`).

1. **Цифровая модель и занятость (30 с).** Станция Алматы-1: схема путей с поездами в движении, парки П / С / Пл, платформы, горловины, депо ЧМЭ3;
   диаграмма движения (план — контур, факт — заливка, операции, окна ТО); индикатор «Онлайн · 2.3 Гц · WS».
2. **Индекс эффективности (45 с).** Шкала 0–100, буква A–E, категория и пороги; динамика; **топ-5 факторов потерь** (наведите на фактор — формула и вес); кнопка «Формула».
3. **Нештатная ситуация (90 с).** «Закрытие пути» (путь 3, 60 мин) → за доли секунды: конфликт «путь закрыт, а назначен», красная штриховка на схеме и диаграмме,
   падение индекса; в «Альтернативных планах» — «Без вмешательства» против вариантов (время расчёта, Σ опозданий, смен пути, **индекс после** и Δ). **Применить** лучший → конфликты исчезают, индекс растёт.
4. **Разрешение конфликта (30 с).** В панели конфликтов — кнопки решений («Перевести на путь…», «Задержать приём…», «Резерв…», «Полный пересчёт»).
5. **Нагрузочный сценарий (60 с).** «×10»: десять разных одновременных сбоев (задержки, закрытия, локомотив, бригада, питание ЭЦ, пакет поездов) — сервер принимает за единицы мс,
   интерфейс не подвисает, через 1–2 с — новые альтернативы. Консольно: `python tools/load_test.py --clients 20 --bursts 3 --multiplier 10`.
6. **Перемотка (30 с).** Ползунок внизу: последние 15 минут; метки — моменты сбоев; «В эфире» возвращает к онлайну; «Воспроизвести».
7. **Отчёт (15 с).** Кнопки PDF / CSV: индекс и факторы, конфликты, события, план, график индекса, занятость путей.
8. **Надёжность канала (30 с).** Остановить сервер → «Нет связи · повтор через N с · попытка k», после запуска — автоматическое восстановление с историей.
9. **Настройки и безопасность (30 с).** «Настройки» под admin: веса и пороги индекса, лимит времени решателя, веса целевой функции — применяются без перезапуска; под диспетчером — только чтение (403).
10. **Наблюдение:** вкладка «Наблюдение» — карта сети КТЖ с тепловой картой и 3D-модель станции (IoT, видеонаблюдение, «песочница» учебных сценариев); сдача дежурства и ночной режим — в «Управлении»; RU / KZ / EN.

Внешний источник данных: `python tools/ws_client_demo.py --station otar` — события с дублями, мусором и перепутанным порядком; в верхней панели растут счётчики «дубли / ошибки / устар.».
